# 文本分块：字形簇安全与上下文开销封顶

> 深度参考文档。改 `src/outbound/chunker.ts` / `grapheme.ts` 前必读。

- **字形簇安全分块（2026-10-20 接入 10.5 `text-grapheme`）**：QQ 单条消息上限 5000 字。框架 `chunkMarkdownText` 按「换行/空白」断点切块——**中文长句没有空白时会在硬上限处直接截断**，切点落在 emoji（代理对 / ZWJ 序列 / 组合符号）中间就把字形切碎，QQ 侧渲染成豆腐块；本地 GFM 表格 fallback 则是**整块不切**，超限消息被平台直接拒收（消息丢失）。`src/outbound/grapheme.ts` 用 `openclaw/plugin-sdk/text-grapheme` 的 `findGraphemeChunkEnd`（2026.10.5 新增子路径，**地板抬至 10.5 后恒在，但发布包不带 .d.ts**）做切点吸附，**带能力探测 + 本地 `Intl.Segmenter` 等价回退**（懒调用 + try/catch，缺失不影响插件加载与分块行为）。**本地回退实现必须逐行对齐官方 `dist/grapheme-*.mjs`**——两处细节漏掉就会出真 bug：**(1) `avoidTrailingHighSurrogateBreak` 的 `end + 1` 兜底分支**——预算只剩 1 个码元且它正好是代理对前半时，退到 `start` 会**零进展**，分块循环 break、整块原样超限被拒收；**(2) 官方契约允许「代理对安全的部分切」**——预算内放不下完整字形簇时，切点可以落在簇内部（只要不切碎代理对），**不要**断言切点必须是簇边界（会误判）。`src/outbound/chunker.ts` 的 `enforceChunkLimit` 对**仍超限**的块做二次切分（优先换行断点 → 空格断点 → 字形簇边界），**续段补回结构上下文**（代码围栏包裹 / 表格表头）并把上下文开销计入切分上限（否则补完反而超限）。**该子路径在地板抬至 10.5 后已纳入 `tests/sdk-surface.test.ts` 的正常守卫**（原先在 `EXEMPT_SUBPATHS` 里豁免，理由「9.1 基线不存在」随抬地板失效）——子路径被删即变红；因它是字面量 require（扫描器看不到属性访问），另有一条名级断言兜住 `findGraphemeChunkEnd`。回退路径本身仍由 `tests/chunker-grapheme.test.ts` 的行为用例兜底——其中含**与官方 10.5 实现的差分测试**（20 个用例的期望值由官方实跑产出，锁定「9.1 用户与 10.5 用户切分结果不分叉」）。

- **结构上下文开销必须封顶，否则超限消息会炸成上千条垃圾消息（2026-10-20 分支评审修复）**：续段要补回围栏包裹 / 表格表头，这部分开销要从切分预算里扣。此前**两个漏洞叠在一起**：**(1) 围栏 info string 取整行**——`line.slice(m[1].length).trim()` 把 marker 之后的**整行**当语言标识，而 LLM 常输出的超长单行（行内 JSON / 行内代码）整行都是 payload，前缀直接膨胀到超限；顺带该切法在**有前导空白**时还会把 marker 的头几个字符当成 info string 的一部分（应按 `m[0].length` 切）；**(2) 负预算被钳成 1**——`Math.max(1, limit - overhead)` 把「前缀本身已超限」的事实掩盖成「每段只剩 1 字符」。两者相乘的后果：一条 5114 字的超限消息被切成 **5110 块、其中 5109 块各 5120 字（全部超限被平台拒收）**。修复照抄框架 `resolveFenceReopenLine` 的**逐级降级**：完整开栏行放得下就用 → 否则降级为裸 marker → 再放不下放弃围栏上下文；info string **只取首个 token**（语言标识；超过 32 字符视为没有语言标识）；表头上下文另加**预算规则**——上下文开销 > 正文预算（overhead > limit/2）时整段放弃上下文按纯文本切（重复的上下文不该比它承载的内容还长）。另补**首刀不得落在围栏开栏行内部**（框架同义约束是 `minProgressIdx`），否则首块只剩一个孤零零的 ```js。修复后同一输入切成 **2 块（5000 + 124）、零超限**，与框架路径同形。**框架路径本来就是对的**——`rt.channel.text.chunkMarkdownText` 存在时走框架，其 `resolveFenceReopenLine` 自带封顶；炸的是**本地 GFM fallback**（runtime 未就绪 / 能力缺失时的安全网），故属「安全网自身有 bug」而非生产主路径缺陷。`tests/chunker-context-overhead.test.ts` 锁定 11 例（末例为伪随机不变量测试：固定种子 300 轮，每块 ≤ 上限 / 内容不丢 / 块数不爆炸）。

- **分块路径的已知残留（低优先级，未修）**：`enforceChunkLimit` 只处理**严格超限**（`length > limit`）的块；框架 chunker 对无空白中文长串是在 windowEnd **精确切出恰好等于 limit** 的块，其保护只有 `avoidTrailingHighSurrogateBreak`（代理对级）——切点落在 ZWJ 序列（如家庭 emoji 的两个人物之间）或组合符号中间时，块仍 ≤ limit、原样放行，豆腐块跨两条消息的残留**在框架路径上依然存在**。真修需「在切点处重锚定」（把被切碎的簇整体挪到下一条、再重切下一条），会改动块边界与「无内容丢失」性质，成本另议，暂不处理。
