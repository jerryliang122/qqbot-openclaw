# SDK 兼容面与 openclaw 版本盯版

> 深度参考文档。AGENTS.md 的「Key gotchas / SDK 兼容」条目是这里的摘要。

**构建基线：openclaw `2026.10.5`**（peer 范围 `>=2026.10.5`，devDependency 精确钉版 `2026.10.5`；2026-10-22 抬地板，此前基线为 2026.9.1）。所有与 openclaw / `openclaw/plugin-sdk` 的交互以 2026.10.5 为最低兼容版本 —— 不得使用仅存在于更新版本中的 API，除非带能力探测与回退；调整钉版前必须重新评估兼容性（钉版历史：2026-09-07 曾钉 2026.9.2——彼时 registry `latest` stable；2026-09-22 降回 2026.9.1；2026-10-22 抬至 2026.10.5，触发信号 = 上游 10.x 系列语义代差带来的兼容成本已超过继续支持 9.x 的收益，且本插件主要部署环境已切 10.x；抬地板时同步确认 openclaw 10.2+ 的 `engines` 已砍 Node 22（`>=24.16.0`），本包无 `engines` 字段故不拦截安装，但 Node 22 用户会有运行时坑；**2026-10-22 决定不补 `engines` 字段**——openclaw 自身已要求 Node ≥24.16，用户装 openclaw 这一步就把门槛挡住了，插件包再设一道没有实际拦截价值，徒增维护面）。2026.9 系列的审批面变化：`ChannelApprovalKind` 新增 `"system-agent"`（OpenClaw 系统变更审批，2026.9.1 stable 起即存在），插件已支持（eventKinds、`buildSystemAgentApprovalText`、button_data `approve:v2:system-agent:...`），且 `resolveApprovalOverGateway` 改用带 `approvalKind` 的规范重载（无 kind 的旧签名已 deprecated，两版签名一致）。

**2026-10-22 抬地板（9.1 → 10.5）实证结论**：抬地板判据满足「上游明确放弃旧版本」（10.2 起删除 9 个子路径、10.5 语义代差）+「主要部署环境已切 10.x」。换版后 typecheck / lint:runtime / build / sdk-surface 守卫 / dispatch 系与 debounce 系单测全绿（**用例数已随守卫增长，现状以 `npx tsx tests/sdk-surface.test.ts` 实跑为准——2026-10-22 记录时为 38 例**）。**10.5 的 canonical session key 文法是本次换版最重要的运行时语义**（详见下条目）。

**2026.10.x 盯版结论（2026-10-12 实测；**历史结论，已被 2026-10-22 抬地板取代**）**：openclaw `2026.10.2` **整体移除了 9 个 plugin-sdk 子路径**——`channel-message`、`channel-lifecycle`、`channel-reply-pipeline`、`command-auth`、`config-runtime`、`discord`、`infra-runtime`、`telegram-account`。本插件实际命中的**只有 `channel-message`**（唯一用法：progress card 的 `formatPlanChecklistLines`），其余 8 个均未引用（approval 侧被删的 `matchesApprovalRequestSessionFilter` / `resolveApprovalRequestAccountId` / `resolveApprovalRequestChannelAccountId` / `createChannelApprovalForwardingEvaluator` 本插件也都没用到）。修复方式是把该 import 迁到 **`openclaw/plugin-sdk/channel-outbound`**——该子路径 9.1 与 10.2 **都在**，`formatPlanChecklistLines` 签名两版一致（10.2 只是把 `plain` 选项标了 `@deprecated` 注明"retain until a breaking SDK release"，本插件未传该选项），故**对基线与新版本同时成立，无需动钉版与 peer 范围**。同批实测无碍：`ChannelApprovalKind`（两版均含 `"system-agent"`）、`replyOptions` 的 `onPlanUpdate` / `suppressDefaultToolProgressMessages` / `allowProgressCallbacksWhenSourceDeliverySuppressed` / `queueModeOverride` / `sourceReplyDeliveryMode`、`room_event` + `message_tool_only`、`resolveToolPolicy`、`appendUsageLine` 在 10.2 均原样存在；10.2 新增 `ChannelGatewayAdapterV2` / `ChannelGatewayContextV2` 是**可选的 gateway V2 契约**（`ChannelPluginForGatewayVersion` 按 `GatewayVersion extends 1|2 = 1` 分派），插件未声明 `apiVersion` 即仍走 V1，无需跟进。10.2 双跑 typecheck / lint:runtime / build / 全量测试全绿（**2026-10-12 记录时为 44 个测试文件，现已增至 60 个**）。**地板决策（2026-10-12 确认；**已于 2026-10-22 被抬地板取代，判据本身仍成立**）：peer 与钉版一并保持 2026.9.1，不因新 stable 抬地板。**判据两条——(1) **钉版必须恒等于 peer 承诺的最低版本**，这是 typecheck 护栏与对外承诺之间的不变式；两者一旦脱钩（peer 还写 `>=9.1`、编译却在 10.2 上跑），我们就测不出"误用旧版没有的 API"，虚假承诺只在用户运行时炸，也正是 channel-message 事故的同类。(2) **只有适配真的切断了旧版本才抬地板**：适配若在新旧两版都成立（本次即如此——迁的是 `channel-outbound` 这个两版共有子路径，10.2 对 `channel-message` 是删除而非改签名，故可绕开），抬地板只会打断正在使用旧版的存量用户、换零能力收益。抬地板应只由这三个信号触发：上游明确放弃该旧版本 / 我们真要用新版独有 API 简化代码 / 存量用户归零。顺带：真抬地板时要一并考虑 openclaw 10.2 的 `engines` 已砍掉 Node 22（`>=24.16.0`），本包无 `engines` 字段故不会在安装期拦截，但会给 Node 22 用户埋运行时坑。**地板说谎的风险由 `tests/sdk-surface.test.ts` 兜底，不靠抬地板**——那才是验证强度。

**2026.10.5 盯版结论（2026-10-20 实测；**历史结论，已被 2026-10-22 抬地板取代**）**：9.1 → 10.5 的 `plugin-sdk` 子路径**净增 29 个 / 净删 9 个**（删的 9 个在 10.2 已删，10.2–10.5 无新增删除；新增：`speech-provider` / `realtime-voice-provider` / `realtime-transcription-session` / `realtime-voice-playback` / `text-grapheme` / `media-ffmpeg` / `secret-egress-runtime` / `websocket-runtime` / `feature-contract` / `feature-plugin` / `control-ui` / `decisions` / `control-ui-link-reader` / `embedding-provider-*` / `provider-*` / `agent-harness-*` / `agent-workspace-runtime` / `worker-task-server` / `session-catalog-paging` / `sqlite-worker-runtime` / `memory-core-host-engine-*` / `code-mode-executor-runtime` / `cli-entry`）。**核心结论：10.5 官方文档里的绝大部分「通道插件最佳实践」在 9.1 就已存在**——本插件用到的 26 个子路径逐个 diff 后，导出面变化仅 5 处：`approval-runtime`（+4/-3）、`approval-native-runtime`（-1）、`channel-inbound`（+10/-1）、`channel-outbound`（+32/-0）、`config-contracts`（+4/-0）、`core`（+7/-0）、`string-coerce-runtime`（+2/-0），其余 19 个子路径**逐字未变**。故**不抬地板也能吃到 10.5 的能力**（2026-10-22 的抬地板决策正是基于这条：兼容成本 > 收益）。**审批面实测无碍**（勿被「10.5 重构了 native 审批 runtime」的说法误导）：`createChannelApprovalNativeRuntimeAdapter` 工厂签名两版一致；`ChannelApprovalNativeRuntimeSpec` 的 `presentation.buildPendingPayload` 参数集逐项相同（9.1 的内联 `ChannelApprovalCapabilityHandlerContext & {request, approvalKind, nowMs, view}` = 10.5 的具名 `ApprovalRequestContext & {nowMs, view}`，而 `ApprovalRequestContext = ChannelApprovalCapabilityHandlerContext & {request, approvalKind}`）；`transport.prepareTarget` / `deliverPending` 的属性集（`plannedTarget` / `request` / `approvalKind` / `view` / `pendingPayload` / `preparedTarget`）两版一致——10.5 只是把内联对象类型重组成具名 context，**通道侧回调签名一字不改**。真正被删的 3 个审批导出（`matchesApprovalRequestSessionFilter` / `resolveApprovalRequestAccountId` / `resolveApprovalRequestChannelAccountId` / `createChannelApprovalForwardingEvaluator`）**本插件都没用到**（后两个是换子路径而非删除：`resolveApprovalRequest*` 仍在 `approval-native-runtime`）。**TTS 配置 schema 两版逐字相同**（`config-contracts` 新增的 `TtsMode` / `TtsPersonaConfig` / `TtsPersonaFallbackPolicy` 只是 9.1 就存在的类型的**重新导出**，`SessionResetMode` 是会话重置策略、**与 TTS 无关**）；多音色/人格全部由 core 裁决（`cfg.tts.personas` + `modelOverrides.allowVoice`），通道侧只需声明 `capabilities.tts.voice`。**群话题（group thread）是 10.5 全新能力**（9.1 全 dist 零命中），配置在**顶层 `cfg.broadcast["<channel>:<peerId>"]`**（不在 `channels.qqbot` 下），值是 agent id 数组或 `{agents, mentionGating?, maxRounds?, maxTurns?}`；`mentionGating` 默认 true、`maxRounds` 默认 1（上限 4）、`strategy` 默认 `parallel`；ACP 绑定会话被 `isGroupThreadRouteExclusive` 排除。**29 个新子路径里 20 个对 TypeScript 消费方等于「无类型」**（exports 无 `types` 条件 **且** package.json 的 `files` 显式排除对应 `.d.ts`）——`text-grapheme` / `media-ffmpeg` / `speech-provider` / `realtime-*` / `secret-egress-runtime` 等若要引入，**必须像现在对裸 `openclaw/plugin-sdk` 和 `text-utility-runtime` 那样补 ambient `declare module` stub**，否则 typecheck 立刻红（TS7016）。**`feature-contract` / `feature-plugin` 不是「通道能力声明」**（那仍是 `ChannelCapabilities`，10.5 只多了 `reactionSlots?: "single" | "multiple"`），而是基于 typebox 的「插件功能 RPC 契约」——把操作/事件一次性暴露给 Control UI、agent 工具、斜杠命令三个面。

- **`tsup` post-build hook** (`tsup.config.ts` 的 `sanitizeDist()`，由 `onSuccess` 触发): rewrites `dist/index.cjs` to alias `new Function` → `new _F` (protobufjs pattern that triggers security scanners). Don't strip this — it's load-bearing.

- **`preload.cjs` symlink**: `openclaw` is a `peerDependency`. When installed via `openclaw plugins install`, the plugin ends up under `~/.openclaw/extensions/openclaw-qqbot/`, and `openclaw/plugin-sdk` must be resolvable from the plugin's `node_modules`. `preload.cjs` synchronously calls `ensurePluginSdkSymlink()` (see `scripts/link-sdk-core.cjs`) which creates a junction `node_modules/openclaw` → the global openclaw install. If you remove or rename `preload.cjs`, the plugin will fail to load when installed via the framework.

- **`package.json` `external`**: `openclaw` and `openclaw/plugin-sdk/**` are external — they are NOT bundled. `dist/index.cjs` does `require('openclaw/plugin-sdk/core')` at runtime. Local dev needs `node_modules/openclaw` as a real install (or symlink to it). Dev copy is exact-pinned to the baseline via devDependency `openclaw@2026.10.5` so typecheck validates against the oldest supported API surface — keep every `openclaw/plugin-sdk` usage compatible with 2026.10.5 (capability probe + fallback if a newer API is genuinely needed) and don't bump the pin without re-checking compatibility. Stable 2026.10.5 satisfies the peer range, so plain `npm install` works; `--legacy-peer-deps` is not required. Note `package-lock.json` is listed in `.gitignore` but is actually tracked — installs will produce a lockfile diff. **裸子路径 `openclaw/plugin-sdk`（无后缀）不在包 exports 里**：运行时 require 会抛 `ERR_PACKAGE_PATH_NOT_EXPORTED`——本插件对它只有 `import type`（会被擦除），且类型由本地 ambient stub 提供；永远不要从裸路径做值导入。

- **`src/openclaw-plugin-sdk.d.ts`**: ambient type stubs for `openclaw/plugin-sdk` subpaths the package doesn't type. 2026-09-07 起包已为 `core` / `setup` / `setup-tools` / `question-gateway-runtime` / `webhook-ingress` 等子路径提供正式 `.d.ts`（原 `src/typings/openclaw-webhook-ingress.d.ts` 已删除），这些 stub 已移除、typecheck 直接验证真实 SDK 类型。当前 stub 只剩两段且**都是必需的**：(1) 裸入口 `openclaw/plugin-sdk`（包既无 exports 也无类型，且代码大量 `import type` 它）；(2) `text-utility-runtime`（包 files 列表仍排除其 `.d.ts`）。升级 openclaw 钉版时先删掉包已提供类型的 stub 段再跑 typecheck——ambient `declare module` 会遮蔽包内真实类型，留着等于没验证。`tests/sdk-surface.test.ts` 的「ambient stub 新鲜度」用例会在包补上 `.d.ts` 时主动报错，不必靠人记。

- **SDK 子路径被删是运行时炸裂，typecheck 不设防 → `tests/sdk-surface.test.ts`（2026-10-12 新增）**：openclaw 删一个 plugin-sdk 子路径时**连 .d.ts 一起删**，tsc 只会报"找不到模块"，但真正致命的是**插件整体加载失败**——`dist/index.cjs` 在加载期就抛 `ERR_PACKAGE_PATH_NOT_EXPORTED`，所有功能全灭，且本地 typecheck 若没覆盖到该子路径就完全无声（2026-10-12 盯版：10.2 整体删了 9 个子路径，插件命中的 `channel-message` 即属此类）。该守卫测试把"插件引用的 SDK 依赖面"固化为可执行断言，**下一次**子路径消失会在 CI 就红：扫描 `src/**/*.ts` + `index.ts` 的全部 `openclaw/plugin-sdk/*` 引用 → 断言每个子路径都在已安装包的 `exports` 内 → 子进程用裸 node 断言每个子路径真能 require 出来（静态具名的值导入另查名级导出）→ 额外断言 `dist/index.cjs` 能被原生 CJS 加载器 require（复刻生产加载路径）。**扫描必须按引号字面量取子路径全集，不能解析 import 语句形态**：初版只匹配静态 `import {…} from`，评审实测确认漏掉四种同样承重的用法（`await import('…/approval-gateway-runtime')` 审批按钮 tap 核心路径、`import('…/question-gateway-runtime')` ask_user 问题流、`getReq()('…/health')` 一类字面量惰性 require、`export {…} from '…/setup-tools'`），下版本子路径删除照样全绿放行；形态会随代码演化增删，解析语句必然再次漏。**豁免要显式登记**（`EXEMPT_SUBPATHS`，默认空），别靠"扫不到"——`webhook-ingress` 虽是 `.catch()` 降级用法也不豁免，子路径被删时 `.catch` 会把故障吞成"webhook 静默失效"，比抛错更难发现。**写这类运行时断言必须放子进程**：openclaw 是 ESM 包、部分依赖（如 `unicorn-magic`）exports 只有 `import` 条件没有 `require` 条件，而 tsx 会 patch `Module._resolveFilename`，在 tsx 进程内直接 require 这些子路径会报 `No exports main defined in unicorn-magic`——那是加载器差异、**不是插件缺陷**，误判会让人去改本来没坏的代码。**具名子句要逐项判 `type`**：`import { fn, type Opts } from '…'` 的 inline `type` 若被剥掉后一律当值导出，接口在运行时不存在会让守卫误报"缺少运行时值"并把人引向不存在的 SDK 缺陷——inline `type` 是本仓库主流写法，扫描器必须支持。

- **Runtime contract probe** (`src/adapter/contract.ts`): `REQUIRED` list is currently **empty**; all capabilities are `OPTIONAL`. The probe still runs on register but only logs degraded features; it will never throw unless someone adds a required entry. Don't rely on it to fail fast on missing APIs.

- **`package-lock.json`**: listed in `.gitignore` but actually tracked in git — regenerate with `npm install` (see the `external` gotcha above) and expect a lockfile diff; don't `npm ci` against a fresh clone.
